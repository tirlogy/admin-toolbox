Why this toolbox?

As an IT administrator, the same questions come up every week: Why does our mail end up in spam? Are SPF, DKIM and DMARC right? Did a record go missing after the DNS move? Does the subnet still fit?

Since February 2024, Google and Yahoo require bulk senders to have valid SPF, DKIM and DMARC records, and Microsoft has enforced the same for Outlook.com since May 2025. If a record is missing, mail is rejected or lands in spam. Small companies notice it too, as soon as newsletters or invoices sent by mail stop arriving.

The usual online checkers show ads, want an account or send mail headers with internal addresses to third-party servers. This toolbox does all the work in the browser. Only DNS lookups go to Cloudflare DNS, just like with any resolver.

What mailbox providers expect

SPF
Lists the servers allowed to send for the domain. At most 10 DNS lookups.
DKIM
Signs every mail so changes on the way are noticed. Keys with at least 1024, better 2048 bits.
DMARC
Tells receivers what to do when SPF and DKIM fail, and sends reports. Start with p=none, then tighten.

Google and Yahoo require this from around 5,000 mails a day to their users, Microsoft for Outlook.com. Sources:

  • Google: Email sender guidelines
  • Yahoo: Sender best practices

Typical workflows

  1. Mail lands in spam

    Run the mail domain check for the sending domain. Red and yellow findings come with a concrete suggestion for the DNS record.

    Mail domain check

  2. A single mail looks suspicious

    Copy the headers (Outlook: File, Properties; Gmail: Show original) and paste them into the header analysis. It shows the route, delays and whether the sender is faked.

    Header analysis

  3. Moving DNS

    Export the zone file at the old provider before the move. Afterwards the DNS diff compares it with live DNS and lists every missing record.

    DNS diff

  4. Planning a network

    Enter a network in the subnet calculator, split it into VLANs or check whether an address belongs to it. IPv4 and IPv6.

    Subnet calculator

What stays local

Only the mail domain check and DNS diff send DNS queries to Cloudflare DNS (fallback Google Public DNS). Everything else runs offline.

Under the hood

C# and .NET 10 compiled to WebAssembly (Blazor). No backend: the app is served as static files from Cloudflare Pages.
